# Codex 项目协作规则

本文件是 Codex 在本项目中的长期工作规则。除非用户明确要求覆盖，否则应持续遵守。

## 1. 开始任何任务前

在修改代码前，优先阅读：

1. `docs/CONTEXT.md`
2. `docs/DECISIONS.md`
3. `docs/STATUS.md`
4. 与当前任务直接相关的代码和文档

不要仅根据当前聊天消息猜测完整需求。

如果聊天指令与仓库文档冲突，以用户当前明确指令为最高优先级，并在完成后同步更新相关文档。

---

## 2. 执行原则

### 先理解，再修改

开始编码前先确认：

- 当前任务要解决什么问题
- 用户目标是什么
- 已经确认了哪些产品 / 设计 / 技术决策
- 哪些内容明确不能修改
- 当前代码实现到什么阶段

### 控制修改范围

优先做最小必要修改。

不要因为实现一个局部需求而无理由：

- 重构无关模块
- 调整无关视觉
- 替换技术栈
- 改变已有交互逻辑
- 删除尚未确认无用的功能

### 不擅自做产品决策

如果 `CONTEXT.md` 或 `DECISIONS.md` 已经规定产品方案，应按照确定方案实现。

如实现过程中发现明显冲突、技术限制或体验风险：

1. 优先寻找不改变产品目标的实现方式；
2. 无法避免时，在 `STATUS.md` 中明确记录；
3. 不要悄悄改变产品方案。

---

## 3. 代码质量

完成修改后，根据项目条件尽可能执行：

- 构建
- lint
- 类型检查
- 自动化测试
- 核心流程手动验证

如果无法执行某项验证，要在最终说明和 `STATUS.md` 中写明。

不要声称没有实际执行过的测试已经通过。

---

## 4. 文档同步

每次完成一个相对完整的任务后，必须更新 `docs/STATUS.md`。

如本次任务改变了产品需求、范围、约束或方案，还应同步更新：

- `docs/CONTEXT.md`
- `docs/DECISIONS.md`

不要让代码状态和项目文档长期不一致。

---

## 5. STATUS.md 更新格式

至少记录：

- 更新时间
- 本次任务
- 已完成
- 修改文件
- 验证结果
- 当前问题 / 风险
- 待完成
- 下一步建议

内容应简洁、客观、方便 ChatGPT 网页版快速读取。

---

## 6. 与 ChatGPT 网页版协作的原则

本项目默认工作模式：

- ChatGPT 网页版：需求分析、产品思考、设计讨论、方案决策
- GitHub：项目共享记忆和事实来源
- Codex：代码实现、修改、测试、工程执行

因此，不需要保存完整聊天历史。

优先把最终有效信息沉淀为：

- `CONTEXT.md`：现在要做什么
- `DECISIONS.md`：为什么这么做
- `STATUS.md`：现在做到哪里

---

## 7. 禁止事项

除非用户明确要求，否则不要：

- 直接覆盖已有重要文档
- 删除用户数据
- 大范围修改无关代码
- 擅自新增依赖
- 擅自改变产品需求
- 用未验证的假设替代仓库中的确定信息
- 把大量过程性聊天内容写入项目文档

项目文档应保留“结论”，而不是完整讨论过程。
