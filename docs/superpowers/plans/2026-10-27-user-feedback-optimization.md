## 3. 逐项需求、缺口与验收

下列“拟修改”均为后续实施位置，不表示本轮已经修改。

### R1｜截图详情默认折叠

- **现状与缺口：** 通用 `render_report` 直接展示全部 labels、证据链和来源；一句话归档无折叠。详细归档已经用 card-details 局部实现。
- **拟修改：** `report.py`；在数据交接中保留完整 labels、来源、版本和 ID。默认主卡保留产品身份、截图和简短参考价值；技术字段及完整来源放可展开区域，不通过删数据减负。
- **验收 A-R1：** `test_report.py` 检查字段未丢失且位于关闭的 details 内；`test_browser_report.py` 验证默认隐藏、展开可见、键盘可用、不影响放大。真实两场景逐卡抽查可追溯性，关键历史/状态边界仍以简短标识防止误读。

### R2｜分类有明确、合理的比较依据

- **现状与缺口：** 分类没有 Python 关键词推断，方向正确；但 group.reason 只验非空，未要求主任务、共同机制、研究价值与成员证据。状态相同也不足以构成比较依据。
- **拟修改：** `SKILL.md` 增加 Agent 分组反例审核；`classification.py` 扩展结构化比较依据与成员解释/证据引用，`pipeline.py` 持久化。多维 labels 继续保留。
- **验收 A-R2：** `test_classification.py` 检查缺依据、无效成员引用、漏分/重复归组、动态组名保留；测试任意产品名，防固定映射。Agent 人工复核迅雷反例及一个有共同机制的跨行业正例：说明共同做法、差异、适用范围与本次价值，而非因“都有服务/钱包”归组。自动化只验证结构与引用，不声称能判定语义质量。

### R3｜小分类并排，提高空间利用率

- **现状与缺口：** `report.py` 每组是独立块级 section，内部固定五列；两份报告均让小组占满整行。既有文本写的是“每组一行五张”，实际独占来自 DOM/CSS，不能把不存在的原文引号当成规则。
- **拟修改：** `report.py` 以分类容器为排版单位；按既定研究顺序让相邻小组在足够宽时并排。组内仍保持连续；大组可在组内换行，窄屏允许自然换行。不使用会回填后续组并改变阅读顺序的 dense 布局。
- **验收 A-R3：** 浏览器几何断言覆盖 2+3、1+1、4+2、6 张大组及 21/45 张展开；可容纳时相邻小组同排，放不下时整组移到下一行，组间不插卡，DOM/视觉顺序一致。在 1440/1280/390 宽度核对卡片可读性和无横向溢出；不通过额外缩小截图填空。保留每组 20→40→全部的独立展开。

### R4｜头部展示研究发现，不展示 Skill 原则

- **现状与缺口：** 通用头部输出 research_goal 和 classification_reason，无 core findings；一句话报告将素材执行原则写进 research_goal 后直接呈现。详细报告的结论先行结构有参考价值。
- **拟修改：** Agent 产出头部发现；新增分析契约（建议 `analysis.py`）、`__main__.py`/`pipeline.py` 正式接入分析文件；`report.py` 渲染。研究目标可作简短范围信息，不冒充发现；规则、统计口径与操作说明进入次要/折叠区域。
- **验收 A-R4：** 分析文件中的发现进入 `report_data.json` 和头部，引用能定位图卡；缺发现不得自动将目标/原则改写成结论。浏览器初始视口以核心判断为主；Agent 阅读检查发现确实来自样本，不能只靠字符串禁词测试。

### R5｜结论先行，提升借鉴判断质量

- **现状与缺口：** 定制报告已有借鉴和限制，但通用链没有可校验分析输入；现有非空 reason/labels 无法承载条件与取舍。
- **拟修改：** `SKILL.md` 明确“可见证据 → 设计机制 → 解决的问题 → 借鉴方式 → 适用条件/取舍/待验证”的分析过程；分析契约关联实际材料。建议每条主要判断记录 observation、mechanism、problem、recommendation、applicability、tradeoffs、evidence_refs；最终命名在实施阶段统一，不照此机械拼接成报告长段落。
- **验收 A-R5：** 新 `test_analysis.py` 校验引用只指向有效竞品或明确用户现状、必需信息缺失有明确错误、观察与推断有区分；正式入口保真传递。人工逐条判断是否回答具体借鉴与代价。一句话场景总结模式/差异/适用场景；详细场景联系现状、目标、约束。另用非“我的”页任务验证没有虎牙业务、产品或结论写死。无证据时明确分析不足，不强凑条数；不把使用频率/效果推断作为事实。

### R5A｜可展开的“现状与问题分析”

- **现状与缺口：** 详细归档已独立放置现状图并默认折叠，统计也实际排除了它；通用 Task、人工截图入口和 renderer 尚无此模块。
- **拟修改：** `task_contract.py` 增加可选现状上下文（用户文字和/或现状图片）；分析契约区分用户描述、视觉观察和设计判断；`pipeline.py` 单独复制现状资产，`report.py` 条件显示关闭的现状模块。现状不加入 competitor materials、classification、coverage/fallback 分母。
- **验收 A-R5A：** 覆盖有图、有明确文字但无图、完全无现状三类输入；前两种按可用信息启用，后一种不生成虚构现状或空壳模块。现状 ID 不得混入竞品组；加入现状前后竞品产品数、截图数和覆盖统计保持不变；搬移目录后现状图仍加载。

### R6｜分类副标题是一句话的有效结论

- **现状与缺口：** 通用模板直接使用 group.reason；归档副标题混有“均为浏览态”“5 张”和操作说明。分类解释与面向读者的小结没有分开。
- **拟修改：** 分类保留比较依据，分析契约为各 group 提供单句 takeaway（或等价字段）；`report.py` 将其作为副标题，详细归组依据收进详情。数量与状态有自己的次要位置。
- **验收 A-R6：** 每组 takeaway 存在且引用正确，不回退到旧 reason 自动冒充结论；人工检查它不重复组名、不堆数量/流程，而说明具体参考价值。Python 不靠句号数量或关键词判断“有效结论”。

### R7｜过程说明整体折叠，以分析小结收尾

- **现状与缺口：** 通用统计在图墙前且全部展开，结尾可能是 fallback；详细报告只折叠了过程内部表格，来源说明整体仍展开。均无综合小结。
- **拟修改：** `report.py` 将来源、筛选、访问范围、候选、统计口径和完整 fallback 等归入默认关闭的过程说明；分析契约提供 synthesis（综合模式/页面亮点/可借鉴行动/待验证事项），作为最后主要模块。影响判断的覆盖限制可保留一句简短提示，详细记录仍折叠。
- **验收 A-R7：** HTML/浏览器检查过程外层关闭，展开后证据和分项计数完整；主要内容最后是综合小结，而非来源表/操作说明。小结引用有效、与头部和分组不矛盾、不逐卡重复。无素材时展示真实不足与下一步，不伪造页面亮点。

### R8｜正式采集前预检来源登录和访问能力

- **现状与缺口：** 已有 browser/text/content 状态和失败 fallback；但没有预检批次、覆盖影响、用户选择、登录后复查与会话内恢复协议。当前独立 Chromium context 无法承接用户已登录浏览器；历史数据也证明同一来源不同标签访问可能不同。
