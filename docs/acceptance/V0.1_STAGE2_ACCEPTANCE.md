## 素材契约与职责

所有来源统一使用 `id`、产品/页面元数据、`image_path`、来源字段、`semantic_status`/`semantic_reason`、`quality_status`/`quality_reason`、`collection_status`、观察字段、备注和失败原因。来源、采集方式、provenance、语义、质量和采集状态均严格校验设计文档枚举。Agent 只提供语义状态；Python 只生成机械质量事实。仅 `semantic_status=accepted`、`quality_status=accepted` 且路径有效时计算为 `collected`；候选网页元数据始终为 `pending`。

## 机械质量规则

使用 Pillow `Image.verify()` 真实解码并再次读取尺寸/格式；支持 PNG/JPEG/GIF/WEBP，扩展名必须与实际格式一致。最低尺寸为 `240x240`，最小文件大小为 256 字节，用于过滤图标、缩略图和空文件，同时覆盖常见手机截图。计算原始文件 SHA-256；相同指纹记录 `duplicate_of` 并保留原始来源信息。外部文件复制到输出目录 `assets/`，JSON 仅写稳定相对路径。

## Fixture 验证

`valid.png`、`valid.jpg` 真实解码通过；`small.png` 尺寸拒绝；`truncated.png`、`not-image.txt` 和仅文件头伪 PNG 拒绝；`mismatch.png` 扩展名/格式不一致拒绝；`duplicate.png` 与 `valid.png` 指纹相同并归并追溯。

## 集成与测试

正式命令：`python3 -m competitor_analysis_skill --task-file task.json --materials-file material-input.json --output reports/<name>`。本地验证确认竞品保持原任务内容，素材复制到 `assets/` 并按语义和质量共同计算状态；无素材时输出空素材结果，不伪装成功。`og:image`/`twitter:image` collector 候选保持 `collection_method=web_candidate`、`semantic_status=pending`、`collection_status=pending`。

完整命令：`python3 -m unittest discover -s tests -v`，实际 `26` 项通过；另行执行 Python 语法检查和 `git diff --check`。
