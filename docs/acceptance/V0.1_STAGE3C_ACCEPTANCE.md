## 本轮范围

本阶段消费 Stage 3B 的 `captures.json`、用户/人工提供的 `manual-captures.json` 和 Agent 产生的 `semantic-reviews.json`。Python 校验审核契约、来源对应关系和状态组合，将 browser、user_upload、device_capture 转成统一 Material，并调用 Stage 2 `process_materials()` 重新执行真实图片机械质量校验。输出独立的 `reviewed_materials.json` 与 `fallback_requests.json`，不覆盖 `materials.json`，不交给分类器或报告。

## Agent Review Contract

Review 必须包含 `target_id`、`target_kind`、`semantic_status`、`product_identity`、`target_page_match`、`page_completeness`、`asset_kind`、非空 `semantic_reason` 和固定的 `review_source=agent_visual_review`。`accepted` 仅允许同时满足 `matched/matched/complete/ui_page`；rejected 必须保留原因。Python 不通过文件名、URL、关键词、OCR、颜色或尺寸比例判断页面语义。

自动化测试验证的是 Agent Review 结构化 handoff 和状态转换，不表示 Python 自身具备页面视觉语义理解能力。

## 来源映射与回退

- Browser capture：`browser/browser_screenshot/online`，页面名来自任务，URL 优先使用 `final_url`。
- User upload：`user_upload/user_provided/user_upload`。
- Device capture：`device_capture/manual_device_capture/device_capture`。
- 每个 captured capture 必须有且只有一个 review；failed/blank 不得接受。所有 manual capture 也必须有 review。
- 只有 semantic accepted、机械 quality accepted 且路径有效才是 collected。每个产品和目标页面生成一条 fallback：存在 collected 为 `resolved`，否则为 `open`。
