# V0.1 第二轮架构设计

更新时间：2026-09-03
适用阶段：阶段 0——第二轮架构设计

本文只定义后续架构和实施边界，不表示其中尚未实现的能力已经存在。本阶段不修改 Python 实现、测试、HTML 模板或现有运行逻辑。

## 1. 当前问题与修正目标

第一轮代码建立了可以运行的工程骨架，但没有满足 V0.1 的产品目标。第二轮以真实任务能否得到可信页面素材为判断标准。

| 第一轮现状 | 只完成的骨架工作 | 第二轮修正目标 |
| --- | --- | --- |
| 需求解析只识别“搜索结果页” | 用正则把一个已知短语映射到页面名 | 由 Agent 识别目标页面、调研目标、平台和范围；不确定时补问，并输出可执行任务 |
| 指定竞品未进入实际筛选 | 数据结构中有 `specified_products`，规划仍使用固定目录 | 用户指定竞品必须进入清单并获得最高优先级；Agent 根据任务动态规划其余竞品 |
| 不同需求仍返回固定 8 个搜索页候选 | 内置目录可用于离线链路测试 | 固定目录仅为 Demo/test fixture；正式任务根据目标页面生成不同范围 |
| 采集器只读取 `og:image` / `twitter:image` | 完成了 HTML 元数据解析和下载尝试 | 元数据图片只能是待验证候选；优先获得浏览器渲染的真实页面截图 |
| 图片质量只看文件头和大小 | 可拒绝明显非图片文件 | Python 校验真实解码、尺寸、完整性、扩展名和重复；Agent 单独确认页面主体与目标页面真实性 |
| 无有效截图仍执行结构分类 | 分类器可以消费任意资产字段 | 只有有效截图才能分类；无有效素材时输出 `unavailable`，缺失素材不进主要图墙 |
| 在线失败记录为未采集但仍生成固定结构报告 | 失败状态和 HTML 占位已存在 | 失败必须可追溯；报告明确缺口，不用占位记录冒充页面观察或分类依据 |

## 2. 完整执行流程

正式流程由 Agent/Skill 编排，Python 作为确定性处理工具。两层之间只通过结构化任务、竞品清单和统一素材记录传递数据。

```text
自然语言需求
  → Agent 解析
  → 必要时补问
  → 结构化任务
  → 竞品清单
  → 来源发现
  → 页面获取或浏览器截图
  → 视觉确认
  → 素材标准化
  → 质量校验
  → 动态分类
  → HTML 报告
```

### 2.1 Agent / Skill 编排层

1. 理解用户目标：识别要比较的页面状态、产品范围、地区、平台、时间或其他限制。
2. 检查信息是否足够。如果目标页面、范围或平台会显著影响结果，则一次提出最小必要补问；补问未得到回答时任务保持 `needs_clarification`，不猜测。
3. 生成结构化任务并确认竞品策略。先放入用户指定竞品，再补充有代表性的动态候选。
4. 为每个竞品发现可追溯来源，调用 UI 数据库、公开网页和浏览器能力；必要时请求用户上传或人工/真机截图。
5. 对每个候选素材做视觉确认：确认产品身份、目标页面、页面主体和页面状态，排除 Logo、分享图、营销海报和不相关图片。
6. 为确认后的素材补充页面观察标签和简短备注，调用 Python 完成标准化、校验、去重和产物生成。
7. 仅将 Python 返回的有效素材交给 Agent 选择分类维度，再调用 Python 生成最终 HTML。

### 2.2 Python 确定性处理层

- 读取并校验结构化任务、竞品清单和素材记录。
- 复制或引用素材到报告目录，标准化路径和字段。
- 校验文件存在、格式可解码、尺寸和状态，计算去重指纹。
- 对重复素材保留一条规范记录并保留来源追溯信息。
- 根据 Agent 已确认的标签整理分组，不推断页面结构。
- 生成 `materials.json` 和可浏览、可点击放大的 HTML 报告。
- 对相同输入执行稳定、可重复的自动化测试；不调用模型、不访问 OpenAI API、不要求 API Key。

## 3. 结构化任务数据契约

任务对象是 Agent 产出的唯一执行计划。除 `request` 外，正式执行所需字段必须显式存在；未知值使用空数组或空字符串，不能用猜测填充。

| 字段 | 类型 | 必填 | 产生者 | 消费者 | 缺失处理 |
| --- | --- | --- | --- | --- | --- |
| `request` | string | 是 | Agent | 记录、报告 | 为空则拒绝任务 |
| `research_goal` | string | 是 | Agent | 竞品规划、分类、报告 | 无法判断时 `needs_clarification` |
| `target_page` | string | 是 | Agent | 来源发现、视觉确认、分类 | 不明确时补问；仍不明确则 `needs_clarification` |
| `regions` | string[] | 是 | Agent | 竞品规划、报告 | 用户未指定时可以为空；若地区显著影响范围且无法推断则补问 |
| `product_scope` | string[] | 是 | Agent | 竞品规划 | 未限定时表示开放范围，由 Agent 规划 |
| `specified_products` | string[] | 是 | Agent | 竞品规划、覆盖率验收 | 没有指定时为空数组 |
| `platforms` | string[] | 是 | Agent | 来源发现、截图、质量校验 | 未知时为空数组并保留未知 |
| `constraints` | string[] | 是 | Agent | 所有阶段 | 没有限制时为空数组 |
| `assumptions` | string[] | 是 | Agent | 审计、竞品规划、报告 | 没有主动假设时为空数组；任何 Agent 主动选择的地区或范围都必须记录 |
| `needs_clarification` | boolean | 是 | Agent | 编排器 | `true` 时停止采集并返回补问 |
| `task_status` | enum: `planned`, `needs_clarification`, `ready`, `blocked`, `completed` | 是 | Agent/编排器 | 编排器、验收 | 信息不足为 `needs_clarification`；可执行为 `ready`；环境或依赖阻塞为 `blocked` |
| `competitors` | competitor[] | 条件必填 | Agent | 来源发现、覆盖率报告 | `needs_clarification=true` 时可为空；否则至少包含规划结果 |
| `planning_strategy` | enum: `user_only`, `agent_only`, `mixed`, `fixture_demo` | 是 | Agent/测试夹具 | 审计、验收、报告 | 同时有用户指定和 Agent 补充时必须为 `mixed`；正式任务禁止 `fixture_demo` |

`competitor` 至少包含 `product_name`、`region`、`product_type`、`reason`、`priority`、`planning_status` 和 `planning_source`。其中 `planning_source` 只能是 `user_specified`、`agent_planned` 或 `fixture_demo`，必须逐项记录该竞品的来源。`planning_status` 只能表示规划阶段，不等同于页面采集成功。

任务状态规则：`needs_clarification` 只能作为任务状态语义（同时可作为布尔触发字段），不能作为素材采集状态。若 `task_status=needs_clarification`，不调用采集器；若为 `ready`，`competitors` 必须反映指定竞品优先和动态规划结果。Python 只校验契约，不替 Agent 决定目标页面或竞品。

`planning_strategy` 由竞品逐项的 `planning_source` 汇总得到：只有用户指定项时为 `user_only`，只有 Agent 规划项时为 `agent_only`，两者同时存在时为 `mixed`；仅使用 fixture 时为 `fixture_demo`。正式任务不得使用 `fixture_demo`。

## 4. 统一素材数据契约

每个来源都必须转换为同一素材记录；分类和报告只消费该记录。

| 字段 | 类型 | 必填 | 责任方 |
| --- | --- | --- | --- |
| `id` | string | 是 | Python 生成并校验唯一性 |
| `product_name` | string | 是 | Agent 判断，Python 校验非空 |
| `page_name` | string | 是 | Agent 判断，Python 校验非空 |
| `region` | string | 是 | Agent 判断/任务继承，Python 校验 |
| `product_type` | string | 是 | Agent 判断，Python 校验 |
| `platform` | string | 是 | Agent 判断或来源元数据，Python 校验 |
| `image_path` | string | 条件必填 | Python 标准化；`collected` 时必须可解析 |
| `source_type` | enum: `ui_database`, `public_web`, `browser`, `user_upload`, `device_capture` | 是 | Agent/采集适配器提供，Python 校验 |
| `source_url` | string | 否 | 采集适配器提供，Python 原样保留 |
| `captured_at` | ISO-8601 string | 否 | 采集适配器或用户提供；未知留空 |
| `collection_method` | enum: `database_asset`, `web_candidate`, `browser_screenshot`, `user_provided`, `manual_device_capture` | 是 | 采集适配器提供 |
| `provenance` | enum: `online`, `user_upload`, `device_capture`, `builtin_candidate` | 是 | Python 标准化并校验 |
| `semantic_status` | `pending`, `accepted`, `rejected` | 是 | Agent 判断 |
| `semantic_reason` | string | 是 | Agent 记录身份、页面匹配和排除理由 |
| `collection_status` | `pending`, `collected`, `rejected`, `needs_manual_capture`, `unavailable` | 是 | Python 根据契约和流程更新 |
| `quality_status` | `pending`, `accepted`, `rejected`, `missing` | 是 | Python 校验 |
| `quality_reason` | string | 是 | Python 生成校验结论 |
| `observed_structure` | string[] | 是 | Agent 基于真实截图观察；无效素材为空 |
| `observed_patterns` | string[] | 是 | Agent 基于真实截图观察；无效素材为空 |
| `notes` | string | 是 | Agent 或采集适配器，未知留空 |
| `failure_reason` | string | 条件必填 | Python/适配器记录失败；成功时为空 |

Agent 负责语义事实并设置 `semantic_status`/`semantic_reason`：产品身份、目标页面、页面主体是否完整，以及是否为 Logo、分享图、营销图或无关页面。Python 负责机械事实并设置 `quality_status`/`quality_reason`：文件存在、扩展名、真实解码、尺寸、损坏情况、路径、来源字段和重复指纹。Python 不判断图片是否为目标页面，Agent 不代替 Python 判断文件是否损坏。只有同时满足 `semantic_status=accepted`、`quality_status=accepted` 且 `image_path` 有效，素材才能进入 `collection_status=collected`。Python 不根据 `product_type` 或 URL 猜测 `observed_structure`。

`og:image` 或 `twitter:image` 只能进入候选队列并标记 `collection_method=web_candidate`、`collection_status=pending`，经过 Agent 视觉确认并通过 Python 校验后才可转为 `collected`。候选本身不能进入主要图墙。

## 5. 任务状态定义

| 状态 | 含义 |
| --- | --- |
| `planned` | 已创建任务，尚未完成信息理解 |
| `needs_clarification` | 目标页面、地区、平台或范围不足，等待用户补问 |
| `ready` | 任务契约完整，可以开始竞品规划和采集 |
| `blocked` | 因网络、浏览器、登录、人工协作或其他外部条件暂时无法继续 |
| `completed` | 已完成本次允许范围内的采集、分类和报告生成；不代表所有竞品都有素材 |

## 6. 素材采集状态定义

| 状态 | 含义 | 是否算采集成功 | 是否可分类/进主要图墙 |
| --- | --- | --- | --- |
| `pending` | 已发现来源或候选，等待获取、语义确认或质量校验 | 否 | 否 |
| `collected` | 已获得与目标页面匹配的真实截图，语义和机械质量均通过 | 是 | 是 |
| `rejected` | 已处理但被语义确认或机械质量规则拒绝 | 否 | 否 |
| `needs_manual_capture` | 公开来源不足，需要用户上传、人工或真机截图 | 否 | 否 |
| `unavailable` | 在本次范围和允许来源内无法获得素材，且没有可执行补充路径 | 否 | 否 |

`needs_clarification` 只能作为任务状态，不能写入素材 `collection_status`。“尝试过在线访问”只能记录为 `provenance=online` 加素材失败状态，绝不描述为 `collected`。没有同时满足 `semantic_status=accepted`、`quality_status=accepted` 和有效 `image_path` 的记录，不得用于页面结构分类。

## 7. 竞品规划规则

1. 用户明确指定的产品先进入 `competitors`，保留原名称和指定顺序，并逐项标记 `planning_source=user_specified`；Agent 可补充少量对象，补充项标记 `planning_source=agent_planned`，但不得用补充对象替换指定对象。
2. 未指定具体产品时，Agent 根据 `target_page`、`regions`、`product_scope`、`platforms` 和 `research_goal` 动态规划代表性竞品，并为每项记录理由和优先级。
3. 固定搜索页目录只能作为 Demo、离线测试 fixture；使用时每个竞品标记 `planning_source=fixture_demo`，任务标记 `planning_strategy=fixture_demo`。
4. 正式流程不得自动回落到固定 8 个搜索页候选。来源失败只改变采集状态，不改变目标页面和竞品规划。
5. 不同页面需求必须产生与页面相关的竞品范围。例如“搜索结果页”与“直播产品的礼物面板”不能共享同一默认清单；礼物面板任务应覆盖用户指定的虎牙、斗鱼、抖音直播、Twitch，并由 Agent 判断其余补充对象。

## 8. 页面采集策略

按可靠性和可验证性组合使用以下来源：

1. **UI 数据库**：从 UI Notes、Refero 等公开设计资料中发现候选。记录原始 URL 和页面上下文，仍需 Agent 确认是否为目标页面。
2. **普通公开来源**：产品官网、帮助中心、官方案例或可信公开页面。HTML 中的 `og:image`、分享图或缩略图只能作为待验证候选。
3. **浏览器渲染截图**：使用可用网页/浏览器能力加载目标 URL，处理必要的等待、滚动、视口和登录提示，截取实际渲染页面；这是动态页面的首选真实页面路径。
4. **用户上传截图**：用户提供的原始截图经过相同标准化、质量校验和视觉确认流程。
5. **人工或真机补充**：公开来源和浏览器无法覆盖的移动 App 或关键状态，在用户授权和配合下由人工/真机完成。

每个适配器必须返回候选或截图及来源、方法和失败原因，不直接写报告。采集器不得把 Logo、分享卡、营销图、概念稿或无法确认页面上下文的图像标记为 `collected`。

## 9. 分类规则

- 分类输入只包含 `collection_status=collected` 且 `quality_status=accepted` 的素材。
- 页面结构标签、观察模式和分类理由由 Agent 根据真实截图观察产生，并写入 `observed_structure`、`observed_patterns`。
- Python 只按 Agent 已确认的标签稳定分组、排序和去重，不根据产品名称、产品类型或 URL 猜测页面结构。
- 若有效素材数量为 0，分类结果为 `unavailable`，原因说明缺少有效截图；`planned`、`pending`、`rejected`、`needs_manual_capture`、`unavailable` 素材不进入主要图墙。
- 报告可单独显示缺失清单，标明产品、目标页面和失败原因，但不能把缺失记录伪装成截图卡片或分类样本。

## 10. 分阶段实施计划

### 阶段 1：需求理解与竞品规划

- **修改范围**：Agent/Skill 入口、任务契约、竞品规划接口；保留 Python 作为结构校验器。
- **明确不做**：不接入截图服务，不改变 HTML，不引入 OpenAI API 或 API Key。
- **文件地图**：新增 `competitor_analysis_skill/task_contract.py`（集中定义任务字段、枚举和契约校验）；修改 `competitor_analysis_skill/requirements.py`（解析 Agent 任务输入，不做竞品决策）；修改 `competitor_analysis_skill/planning.py`（消费任务并输出逐项 `planning_source` 与任务级 `planning_strategy`）；新增 `tests/test_task_contract.py`（契约和状态组合测试）；修改 `tests/test_mvp.py`（保留现有回归测试）。每个文件只负责契约、需求解析、竞品规划或对应测试。
- **测试内容**：搜索结果页、礼物面板、指定竞品、缺少关键信息补问、fixture 标记和非固定候选断言。
- **通过标准**：两个验收任务得到不同 `target_page` 和竞品范围；指定竞品全部在清单中且优先级最高；正式任务无固定 8 项回落。
- **停止条件**：无法可靠判断目标页面或范围时保持 `needs_clarification`；任何实现仍依赖固定目录作为正式规划则停止进入下一阶段。

### 阶段 2：素材接入与图片质量校验

- **修改范围**：统一素材适配器、字段标准化、文件/尺寸/解码/完整性/去重校验。
- **明确不做**：不把元数据图片直接当截图；不实现浏览器自动化；不修改分类决策。
- **文件地图**：新增 `competitor_analysis_skill/materials.py`（统一素材字段和状态标准化）；修改 `competitor_analysis_skill/quality.py`（只执行机械质量校验）；修改 `competitor_analysis_skill/collector.py`（接收来源结果并写入统一记录，不做视觉判断）；新增 `tests/test_quality.py`（机械质量和字段校验测试）；新增 `tests/fixtures/materials/`（可解码、损坏、重复等离线素材）。每个文件只负责素材契约、质量校验、采集适配或对应测试数据。
- **测试内容**：文件存在、真实解码、图片尺寸、文件损坏、扩展名、重复图片、路径和来源字段；不测试 Logo、分享图、营销图、产品身份或目标页面匹配。
- **通过标准**：所有来源输出同一契约；Python 只根据机械结果设置 `quality_status`；`collected` 必须同时满足语义和机械质量通过；失败原因可追溯。
- **停止条件**：质量校验器声称能判断图片是否为目标页面，或把不可解码/损坏图片接受为有效素材。

### 阶段 3：Agent 搜索、浏览器和截图工作流

- **修改范围**：来源发现编排、浏览器渲染截图适配器、用户上传和人工/真机补充接口。
- **明确不做**：不承诺所有站点无需登录即可访问；不把网络受限环境描述为产品能力；不新增 OpenAI API 接入。
- **文件地图**：新增 `competitor_analysis_skill/source_discovery.py`（按任务发现候选来源）；新增 `competitor_analysis_skill/browser_capture.py`（浏览器渲染、视口和截图）；新增 `competitor_analysis_skill/manual_capture.py`（用户上传/人工真机补充记录）；新增 `tests/test_semantic_review.py`（视觉语义确认测试）；新增 `tests/test_capture_workflow.py`（截图工作流和失败降级测试）。每个文件只负责来源发现、浏览器截图、人工补充或对应测试。
- **测试内容**：公开静态页、动态页等待与截图、截图来源追溯、访问失败降级、用户上传接入；Logo 排除、分享图排除、营销图排除、产品身份确认、目标页面匹配、页面主体完整性均在本阶段由 Agent 语义测试覆盖。
- **通过标准**：至少获得可验证的真实页面截图；Agent 设置正确的 `semantic_status` 并能排除非页面素材；不可获取项进入正确失败状态。
- **停止条件**：只能取得 `og:image`/缩略图、浏览器截图为空或无法证明页面身份时，不能宣称阶段通过。

### 阶段 4：动态分类与 HTML 报告

- **修改范围**：分类输入过滤、Agent 标签接口、报告图墙与点击放大交互。
- **明确不做**：不根据产品类型自动推断页面结构；不把缺失素材放入主要图墙；不扩展大篇幅竞品分析。
- **文件地图**：修改 `competitor_analysis_skill/classification.py`（仅消费有效素材和 Agent 标签进行稳定分组）；修改 `competitor_analysis_skill/report.py`（生成图墙、缺失清单和点击放大 HTML）；修改 `competitor_analysis_skill/pipeline.py`（编排契约状态和报告输入）；新增 `tests/test_classification.py`（动态标签分组测试）；新增 `tests/test_report.py`（HTML 结构和放大交互测试）；新增 `tests/test_browser_report.py`（实际浏览器打开与点击验证）。每个文件只负责分类、报告渲染、流程编排或对应测试。
- **测试内容**：多维度标签、零有效素材、混合成功/失败素材、分组稳定性、图片点击放大和移动端浏览。
- **通过标准**：只有有效截图有分类和图墙卡片；无素材时显示 `unavailable`；HTML 可打开并点击查看完整截图。
- **停止条件**：报告仍显示无效素材为样本，或浏览器实际打开/放大验证失败。

### 阶段 5：端到端验收

- **修改范围**：验收任务、测试数据、运行记录和发布检查。
- **明确不做**：不以离线 fixture 结果替代真实来源验收；不因数量达标而放宽页面真实性。
- **文件地图**：新增 `tests/test_acceptance_tasks.py`（任务 A/B 的端到端数量与状态断言）；新增 `tests/fixtures/acceptance/`（仅存放明确来源的验收输入）；修改 `docs/acceptance/V0.1_MVP_ACCEPTANCE_REPORT.md`（记录真实运行结果和阻塞）；新增 `reports/acceptance/README.md`（说明验收产物目录和来源追溯）。每个文件只负责验收断言、验收输入、验收记录或产物说明。
- **测试内容**：任务 A、任务 B 全链路，覆盖率、来源、截图真实性、排除规则、分类和 HTML 交互。
- **通过标准**：见第 11 节，所有硬性检查通过且本地与远端提交状态一致。
- **停止条件**：任一硬性检查失败，或环境阻塞导致无法确认真实截图/浏览器交互；应记录阻塞，不得标记 MVP 完成。

## 11. 最终验收任务

### 任务 A

用户输入：“帮我搜集一下海内外热门产品的搜索结果页。”

验收检查：

- `target_page` 为搜索结果页，地区覆盖国内与海外。
- 竞品由 Agent 规划，不来自固定 8 项目录；清单能说明每项代表性理由。
- 至少覆盖 3 个不同产品，至少获得 4 张真实有效截图；国内和海外均有有效样本。
- 每个计入样本的素材都有真实页面截图、来源和采集时间或明确未知值，并同时满足 `semantic_status=accepted`、`quality_status=accepted` 和有效 `image_path`。
- Logo、分享图、营销图和无法确认页面上下文的图片被拒绝或保持待验证。
- 只有有效截图进入分类；HTML 图墙可浏览并点击放大。

### 任务 B

用户输入：“帮我搜集一下国内外热门直播产品的礼物面板，重点关注虎牙、斗鱼、抖音直播和 Twitch。”

验收检查：

- `target_page` 为直播产品礼物面板，而不是搜索结果页。
- `specified_products` 至少包含虎牙、斗鱼、抖音直播和 Twitch，且四项优先处理并出现在竞品清单中。
- 其余竞品由 Agent 依据直播产品、地区和平台动态补充，不能复用任务 A 的固定搜索候选。
- 至少从虎牙、斗鱼、抖音直播和 Twitch 中的 2 个指定产品获得真实有效礼物面板截图；其余无法获得的产品必须记录真实失败原因。
- 获得的素材必须是礼物面板真实页面截图；搜索页、Logo、分享图和营销图不得计入有效样本。
- 只有有效截图获得页面结构/设计模式分类；无效或缺失项显示为相应状态，不进入主要图墙。
- HTML 报告可直接打开，截图可点击放大查看完整页面。

两项任务必须产生不同的目标页面和竞品范围；这既是功能验收，也是防止硬编码回退的回归检查。

### 整体硬性门槛

- 两项任务整体至少覆盖 2 种不同来源或采集方式。
- HTML 报告必须实际打开验证，并至少完成一次真实图片点击放大。
- 任一数量门槛、语义确认、机械质量或浏览器交互门槛未达到时，V0.1 MVP 不得判定为完整通过。
- 环境阻塞只能记为 `blocked` 或对应素材失败状态，不能降低验收标准或以 fixture 替代真实结果。
