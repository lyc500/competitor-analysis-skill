# V0.1 真实用户场景测试归档

本目录归档了两个真实 Codex 任务的测试过程、结构化过程记录、截图资产和最终 HTML 报告。它们不是 fixture、静态演示或历史测试数据；两个任务均由用户在实际使用中发起并完成了对应的素材搜集与报告生成。

## 两个测试场景

| 场景 | 用户输入形态 | 报告 |
| --- | --- | --- |
| [一句话测试：国内外 App “我的”页截图](./one-sentence-my-pages/README.md) | `帮我搜集一下国内外知名app“我的”页的竞品截图` | [打开报告](./one-sentence-my-pages/report.html) |
| [详细需求测试：虎牙“我的”页改版竞品参考](./detailed-my-page-redesign/README.md) | 明确现状、改版目标、常用功能、会员与任务中心约束 | [打开报告](./detailed-my-page-redesign/report.html) |

## 阅读方式

- 先阅读每个场景目录下的 `README.md`，了解输入、范围、报告结果和证据边界。
- `report.html` 是面向产品设计阅读的最终报告；同目录的 `assets/` 是报告使用的本地截图。
- JSON、TSV 和 Markdown 文件是过程证据，用于追溯来源尝试、候选登记、审核、分类和报告输入。
- 两个场景都保留了外部来源 URL，但这些 URL 可能受登录、权限或站点当前状态影响；本归档中的本地截图用于复核当时报告，不代表外部站点永久可访问。
- 为控制仓库体积，未复制原始候选池中的全部 raw 图片，也未复制一次性生成脚本；候选处置和审核结果保留在结构化记录中。

## 对 Skill 的验证意义

这两个场景分别覆盖：一句话需求的语义补全与候选规划，以及带业务目标的多维筛选、分类和建议生成。它们与本仓库当前 `SKILL.md`、证据契约和报告统计实现一起提交，便于后续 GPT 直接查看“需求 → 发现 → 审核 → 素材 → 分类 → 报告”的完整链路。
